# /zenn-write — Zenn 技術記事執筆

Zenn 技術記事を「執筆 → 校閲 → 編集 → プレビュー → 公開」まで一気通貫で支援する。

- **対象リポジトリ**: あなたの Zenn 連携リポジトリ（`articles/` を持つ GitHub 連携リポジトリ）
- **記事の置き場**: `<zenn-repo>/articles/*.md`（1 記事 = 1 ファイル）

> 出典: [Zenn CLI ガイド](https://zenn.dev/zenn/articles/zenn-cli-guide) / [Markdown 記法](https://zenn.dev/zenn/articles/markdown-guide) / 技術記事の構成は [renn 「世界一見られる技術ブログの書き方」](https://zenn.dev/renn/articles/454ea916a29236)・[seya 「本気で技術記事を書く時のプロセス」](https://zenn.dev/seya/articles/47ecabce77d68c) を参照。

## 引数

```
/zenn-write [テーマ（任意）] [type: tech|idea（既定 tech）]
```

## 実行手順

### Step 1: 記事の骨子を決める

ユーザーに確認（未指定なら質問）:

- **テーマ / 解決する課題**（誰の何を解決するか）
- **type**: `tech`（技術知見）/ `idea`（考え・ポエム）
- **想定読者**（前提知識のレベル）
- **オチ**（読者が最後に持ち帰るもの）

### Step 1.5: ヒヤリングで素材を引き出す（★着手が重いときは必須）

冷たく AI に下書きを書いてもらうと「つまらない（AI臭）」になる。書き手が完璧主義で着手が重い場合はここを挟む。

`/zenn-interview [テーマ] [slug]` を実行し、**課題・エラー原文・意外な発見・選択理由・山場**を本人から引き出して `drafts/zenn-interview-*.md` に素材化する。以降の下書きはこの素材の言葉を核にする。

### Step 2: 構成テンプレ（技術記事）

見出しは **`##`（h2）から**。h1 はタイトルが担うので本文で使わない。

```
## はじめに（課題とゴール）   — 何ができるようになるか。冒頭で結論・完成物を見せる
## 前提 / 環境              — OS・バージョン・事前準備（再現性の担保）
## 手順（本論）             — 見出しで段階分け。最小で動くコードを提示
## ハマりどころ             — 出たエラーを原文で載せ、原因一言＋回避策（★差別化点）
## まとめ                   — 要点の再掲と次の一歩。参考リンク
```

> 差別化は「自分の失敗をそのまま書く」こと。エラーメッセージは原文で載せる。

### Step 3: frontmatter ＋ 本文を書いてもらう

新規ファイルは `<zenn-repo>/articles/<slug>.md`（slug: 12-50字、小文字英数・ハイフン・アンダースコア）。
zenn-cli で雛形生成も可: `npx zenn new:article`

```yaml
---
title: ""          # 1 キーワードで具体的に
emoji: "🛠"        # サムネ用の絵文字 1 つ
type: "tech"       # tech or idea
topics: []         # 例: ["typescript", "nextjs"]（小文字・実在タグ）
published: false   # 執筆中は必ず false（公開されない）
---
```

**Zenn 独自 Markdown（本文で使う）:**

| 用途 | 記法 |
|------|------|
| ファイル名付きコード | ` ```ts:app.ts ` |
| 差分表示 | ` ```diff ts ` の行頭に `+` / `-` |
| メッセージ | `:::message` … `:::` |
| 警告 | `:::message alert` … `:::` |
| 折りたたみ | `:::details タイトル` … `:::` |
| リンクカード | URL を単独行に貼る |
| GitHub 埋め込み | ファイル URL（`#L1-L10` で行指定可） |
| 数式 | インライン `$a \ne 0$` / ブロック `$$…$$` |
| 画像幅 | `![](url =250x)` |

**執筆ルール:**
- コードブロックは**必ず言語指定**。例は「**最小で動く**」5 行以内を目安
- スマホ可読性のため 3〜4 文ごとに段落を分ける
- 抽象語で水増ししない。手順は再現できる粒度で

### Step 4: 校閲 → 編集（品質ゲート）

下書きができたら順に回す。

1. **校閲**: `/koetsu <記事パス> standard` — 表記ゆれ・誤字・ら抜き・一文長など（土台が ja-technical-writing プリセットで技術文に最適）
2. **編集**（構成に不安があれば）: `editor` エージェントに渡し、課題→まとめの流れ・熱量・見出し順を診断

### Step 5: ローカルプレビュー

```
cd <zenn-repo> && npx zenn preview   # localhost:8000 で確認
```

見出し階層・コードのハイライト・埋め込み表示を目視確認する。

### Step 6: 公開（★人間承認ゲート）

公開は**外部公開・実質不可逆のライブ操作**。**記事管理者の明示承認なしに実行しない。**

承認を得てから:
1. frontmatter を `published: true` に変更
2. `<zenn-repo>` で commit → `git push origin`（→ Zenn が GitHub 連携で自動同期・公開）

## 文体

- **Zenn は技術記事。エッセイを書きすぎない。** 個人的な話は導入に留め、本体は技術面を明快・簡潔に書く。
- 導入・所感の地の文は温度を持たせつつ留保・非鼓舞調に。手順・事実の本体は明快・簡潔に言い切ってよい。

## 注意事項

- 執筆中は `published: false` を厳守（誤公開防止）
- 技術記事はこのスキルで対応する
