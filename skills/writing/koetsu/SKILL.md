# /koetsu — 日本語校閲・校正

日本語文章を客観ルールで校閲し、**赤入れ形式で指摘**する。書き手の声を保護し、勝手に全文リライトしない。

> **設計思想**
> - 校閲は客観・機械的な作業。主観的な構成・作風の助言は `editor` エージェントの担当。
> - **指摘ベース**。原文を勝手に書き換えず、箇所・理由・修正案を提示する。
> - **voice を守る**。LLM は明確さを求めて声やリズムを削りがち（over-edit）。表記・誤用は直し、文体・リズムは指摘に留める。
> - ルールの根拠: [textlint-ja](https://github.com/textlint-ja)（MIT）のルールプリセット。AI臭は [humanizer-ja](https://github.com/gonta223/humanizer-ja) を参照。

## 引数

```
/koetsu [対象ファイルパス or 貼り付けテキスト] [レベル: light|standard|strict（既定 standard）]
```

## 実行手順

### Step 0: textlint があれば併用（任意）

機械チェックは LLM の推測より決定的な textlint が優先。存在すれば実行して結果を取り込む:

```
npx textlint --preset ja-technical-writing <file>   # 無ければ Step 1 の目視チェックのみ
```

無い場合はスキップして Step 1 の観点で目視校閲する。

### Step 1: チェック観点（textlint-ja 準拠）

**A. 表記・用字用語**
- 表記ゆれ（例: 行う/おこなう、できる/出来る、ください/下さい）— 文書内で統一
- 漢字/かなの使い分け、送り仮名の統一
- カタカナ語は全角統一（半角カナ禁止）、英数字の全半角統一

**B. 文法・誤用**
- ら抜き言葉（見れる→見られる）
- 二重否定（〜なくもない 等の分かりにくいもの）
- 同一助詞の連続使用（「の」「が」の連続など、min interval 1）
- 二重敬語・敬語の誤用
- 「ですます」と「である」の混在
- 重ね言葉・同語反復（ja-no-successive-word）

**C. 読みやすさ**
- 一文が長い（目安 100 文字超）
- 読点が多い（一文に 3 つ超）
- 連続する漢字が長い（6 文字超）
- 冗長表現（ja-no-redundant-expression）、弱い表現（「かもしれない」等の曖昧さ）

**D. 機械的異物（コピペ由来）**
- NFD 濁点（Mac 由来の分解濁点）、制御文字、ゼロ幅スペース
- 括弧・引用符の対応漏れ（開き閉じ不一致）
- IME 誤変換・不自然なアルファベット混入

**E. 事実・固有名詞（要確認フラグ）**
- 数値・日付・単位・固有名詞・引用の整合。断定できないものは「要確認」として挙げる（勝手に事実を創作しない）

**F. AI 臭（humanizer-ja パターン、任意）**
- 太字＋コロンの箇条書き濫用、3 項強制、全角ダッシュ乱用
- 説教くさい導入、接続語の過多、均一な敬語、「することができます」の多用、無感情な結び

### Step 2: 赤入れ出力

指摘を表で提示する。重要度: 🔴必須（誤字・誤用・異物）/ 🟡推奨（読みやすさ）/ 🔵任意（好み・作風）。

```markdown
## 校閲結果（レベル: standard / 指摘 N 件）

| 箇所 | 種別 | 指摘 | 修正案 | 重要度 |
|------|------|------|--------|:---:|
| L12「見れる」 | ら抜き | ら抜き言葉 | 見られる | 🔴 |
| L20 一文88字 | 長文 | 一文が長く読点4つ | 2文に分割（案: …） | 🟡 |
| L31「〜という点において」 | 冗長 | 回りくどい | 〜で | 🔵 |

### 要確認（事実・固有名詞）
- L45「2024年」— 前段の記述と年がずれている可能性。原典確認を。

### 総評
- 表記統一: 「行う/おこなう」が混在（8:3）。「行う」に寄せる推奨。
- 全体所見: （1-2文）
```

### Step 3: 反映（任意・確認後）

ユーザーが希望した場合のみ 🔴 を Edit で反映。🟡🔵 は原則ユーザー判断。**一括置換で声を潰さない**。

## 注意事項

- 校閲は「正しさ」を担保する作業。「良い構成・作風」への踏み込みは `editor` エージェントへ回す。
- koetsu は汎用の校閲スキルです。
