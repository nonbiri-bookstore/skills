# /zenn-interview — 技術記事ヒヤリング

AI が「聞き手」として書き手にインタビューし、技術記事の素材を引き出す。
**完璧主義で 0→1 に着手できない書き手のための、着手ハードルを下げる仕組み。**

- 前段: `zenn-write` Step1（骨子）
- 後段: 引き出した素材を核に `zenn-write` Step3（下書き）へ

## 引数

```
/zenn-interview [テーマ（任意）] [slug（任意）]
```

## 中核原則（この2つを外さない）

1. **選択肢・構造で攻める。AI は本文（prose）を書かない。**
   - 完璧主義者は「創る」で固まり「選ぶ・直す」は即答できる。だから開放質問より**具体的な二択・叩き台の構造**を出す。
   - ただし叩き台として本文を書かない。中身の言葉は**必ず本人から取る**。AI が書いた文に反応させると「つまらない（AI臭）」が再発する。

2. **取材の基本技法を守る。**
   - 1問ずつ質問する
   - 相手の言葉を拾って返す（プローブ）
   - 尋問調にならない（詰問しない）
   - 脱線を止めない（脱線の中に本音がある）
   - 沈黙を待つ（すぐ次の質問を出さない）
   - **2:8 で本人が多く喋る**（AI は聞き手に徹する）

## 実行手順

### Step 1: 素材の的を絞る（選択肢で）

開放質問（「何について書く？」）で始めない。**具体的な選択肢**を出して選ばせる。

- 「この記事、"何ができるようになる話"？ 候補: A / B / C。近いのは？」
- 「読者は 初心者 / 同じ課題で詰まった経験者 のどっち向け？」

### Step 2: 深掘り（3-5ラウンド、1問ずつ）

技術記事で引き出す観点。**直接聞かず、選択肢や具体プローブで**引き出す。

| 観点 | 引き出し方（例） |
|------|----------------|
| 解決した課題 | 「これが無いと何が困る？ 具体的に一番イラッとした瞬間は？」 |
| つまずき・エラー | 「途中でハマった？ そのときのエラー文、そのままコピペできる？」（★原文が命） |
| 意外な発見 | 「やってみて "え、そうなの" だったことある？」 |
| 選択の理由 | 「なんで X にした？ Y じゃなく X なのはどこが効いた？」 |
| 山場の指名 | 「読者に一番刺さるの、この3つのどれ？」 |

**プローブ**: 本人が言った引っかかる表現をそのまま返す（「"二度手間になった"、そこ詳しく」）。

**やってはいけないこと**:
- ❌ AI が本文の叩き台を書いて反応させる
- ❌ 1回に2問以上
- ❌ 「何が言いたいんですか」（要約の強制）
- ❌ 相手の回答をすぐ整理・分析する（まず受け取る）

### Step 3: 素材整理

```markdown
# zenn-interview: [テーマ]
日付: YYYY-MM-DD
slug: [slug]

## 解決する課題（本人の言葉）
## つまずき / エラー原文
（コピペされたエラーを一字一句そのまま）
## 意外だった発見
## 技術選択の理由
## 山場候補（本人が指名した順）
## 本人の印象的なフレーズ
（一字一句変えない。下書きで温存する語彙）
## まだ聞けていないこと
```

保存先: `drafts/zenn-interview-YYYYMMDD-slug.md`

### Step 4: 確認

> これが素材のまとめです。
> - 足りない話・言い方の違いは？
> - この山場で下書きに進んでいい？

追加したい話があれば追加ラウンド。よければ `zenn-write` Step3（下書き）へ。
下書きは**この素材の言葉を核にし、エラー原文・山場をそのまま活かす**。

## 注意事項

- **main context で実行する**。人間との対話が本質。fork しない。
- トーンは「取材」でなく「一緒に整理するおしゃべり」。
- 5ラウンド超で「そろそろまとめる？」と提案してよい。
- 素材が薄い箇所は無理に埋めず「まだ聞けていないこと」に残す（AIが事実を創作しない）。
